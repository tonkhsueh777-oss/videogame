# 剑影魔踪 · 手机版互动影片

9:16、HTML/CSS/Vanilla JavaScript，单一主播放器，七段影片和四个结局。

## 在线地址

https://tonkhsueh777-oss.github.io/videogame/

## 七段影片

影片已包含在 `media/` 中，保持以下文件名：

| 剧情 | 文件名 |
| --- | --- |
| 开场：女剑客面对魔王 | `01_intro.mp4` |
| 分支 A：拔剑迎战 | `02A_fight.mp4` |
| 分支 B：退入遗迹 | `02B_escape.mp4` |
| 结局 A1：刺向核心 | `03A1_core.mp4` |
| 结局 A2：斩断石链 | `03A2_chain.mp4` |
| 结局 B1：启动封印 | `03B1_seal.mp4` |
| 结局 B2：冲过吊桥 | `03B2_bridge.mp4` |

网页直接读取这些 MP4；没有 Base64、Blob 或整文件 fetch。

## 互动结构

- 开场：向左滑动招架，或向右滑动闪避。
- 迎战：向上刺向核心，或向右下斜划斩断石链。
- 逃离：长按封印 900ms，或向右冲过吊桥。
- 每个招式也可轻点；长按超过 300ms 后提前松手只取消蓄力，不触发点击备用。
- 剩余约 1.8 秒时出现操作，影片结束后仍可操作。
- 四结局保留：破魔、借势、封魔、断桥。可重新挑战或返回上个选择所在片段。

## 手机加载

- 点击进入后才播放有声影片，保留 `playsinline` / `webkit-playsinline`，无原生 controls。
- 每次只请求当前分支，没有临时预加载播放器；浏览器可以用多个 HTTP Range 请求分段加载同一影片，这不等于每次完整重下载。
- 七段 MP4 从合计 11,018,707 字节降为 3,306,875 字节（减少约 70%）。维持 360×640、24fps、8 秒及原剧情；H.264 Main/yuv420p、AAC、faststart。文件名和路径未改。
- 封面从 937,055 字节降为 106,809 字节；只做缩放和重新编码。
- 等待超过 20 秒仅显示慢网提示，保留当前请求和已缓冲数据。只有真实媒体错误才显示失败。
- 用户明确点“重新连接当前影片”才重新请求；尽量恢复当前片段时间。重复点击不会立即重置请求。
- 缓冲恢复可通过实际推进的播放时间解除遮罩，不依赖单一视频帧回调。
- 攻击反馈位于加载层上方，切换时保留上一画面并显示已接受的招式。

## 本地验证

仅测试需要 Node.js；部署游戏没有运行时依赖。

```sh
npm ci
npx playwright install chromium webkit
npm test
```

测试自动启动 Range 静态服务器，检查 `/videogame/` 子路径，端口 18770 必须空闲。覆盖 Chromium/WebKit 手机视口、四个结局、手势、长按、触摸点击、重复选择、网络错误、慢网不自动重载、缺失帧回调恢复及继续播放请求悬挂。

2026-09-23 固定网络对比（Chromium 模拟 Pixel 7、512kbps、180ms 延迟、本地 Range 服务）：点击进入至出现 QTE 从约 35 秒降为约 9 秒。该结果只描述受控限速条件，不是实体手机或用户运营商线路的测速结果。手机流量与电脑 Wi-Fi 不同，GitHub Pages 在不同线路的延迟仍需实际确认。

`Settings → Pages → Build and deployment → Source → GitHub Actions`
